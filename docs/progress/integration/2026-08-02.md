- 원문 문서가 추가·교체되면 지원 스크립트로 문서 등록을 다시 실행해야 한다.

### Decisions
- 안정적 일반 지식과 검증이 필요한 지식을 질의 분류로 분리한다. 전자는 모델 지식을 허용하고 후자는 검증 근거를 필수로 한다.
- 외부 문서 DB 오류는 사용자에게 내부 세부 정보를 노출하지 않되 `QUERY_ERROR`로 구분해 운영자가 원인을 추적할 수 있게 한다.
- 문서 retriever 점수는 데이터 MCP 근거와 동일한 수치 범위로 가정하지 않는다. 현재 로컬 검색기의 보정값 `0.12`는 대표 사례에서 회귀를 막지만, 추후 라벨 평가로 재조정한다.

### Next Steps
1. 라벨된 사내 문서 질의셋으로 문서 최소 점수와 top-k의 recall/precision을 측정한다.
2. 원격 Document MCP transport와 Redis/freshness를 포함한 운영형 E2E를 실행한다.
3. 새 원문 문서 반영 시 등록 스크립트와 대표 RAG API 검증을 함께 수행한다.

### Learnings
- RAG 실패는 DB 접근, 문서 등록, 검색 점수 보정, evidence 정책이 서로 다른 단계이므로 HTTP 오류만으로 하나의 원인으로 취급하면 진단이 지연된다.
- fake 계약 테스트 통과 뒤에도 대표 실환경 API를 확인해야 실제 연결·등록·점수 스케일 문제를 발견할 수 있다.
- 미구현 설계 골격은 정본과 병존할수록 import 경계와 소유권을 흐리므로 계약이 없는 상태에서는 호환 계층으로 남기지 않는 편이 명확하다.
