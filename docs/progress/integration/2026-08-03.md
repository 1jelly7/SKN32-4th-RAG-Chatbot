### Scope

- 포함: 계정 인증·세션 API, 역할별 데이터베이스 접근 권한, 권한 전파·캐시 격리, 계정 시드 절차, 로그인 UI, 단위·통합·브라우저 검증

### Changes

- `admin`, `hr`, `finance` 역할의 허용 데이터베이스 범위를 정의하고, 인증된 사용자 정보가 Chat API·그래프·MCP 호출에 전달되도록 구현했다.
- 로그인·로그아웃·현재 사용자 확인 API와 HttpOnly 세션 쿠키를 추가하고, 보호된 Chat API가 인증되지 않은 요청을 거부하도록 했다.

- 캐시 키에 역할과 허용 데이터베이스 범위를 포함해 서로 다른 권한 사용자의 결과가 섞이지 않도록 했다.
- 계정 스키마·시드 스크립트를 추가했다. 시드 실행의 필수 비밀번호 환경 변수 오류는 `.env`에 필요한 시드 비밀번호 값을 설정하지 않은 것이 원인이며, 실행 전에 해당 환경 변수를 제공하도록 절차를 정리했다.
- 모든 이후 테스트는 Anaconda `skn_3rd` 가상환경의 Python으로 실행했다.
- 로그인 성공 직후 진행 중이던 `/api/auth/me` 요청의 오래된 결과가 UI를 다시 로그인 상태로 되돌릴 수 있는 경쟁 조건을 방지했다.
- 실제 화면 전환 장애의 직접 원인을 수정했다. `.login-screen`의 `display: grid`가 `hidden` 속성의 기본 숨김 처리를 덮어 로그인 오버레이가 계속 보이던 문제를 `.login-screen[hidden] { display: none; }`로 해결했다.

### Decisions

- 세션은 브라우저 JavaScript에서 접근하지 않는 HttpOnly 쿠키로 유지한다. UI 상태만으로 권한을 신뢰하지 않고, Chat API와 MCP 데이터 도구 양쪽에서 권한을 검증한다.
- 브라우저의 `hidden` 속성에 대해 명시적 CSS 규칙을 둬 레이아웃 선언이 기본 숨김 동작을 덮어쓰지 않게 한다.
- 로컬 시드 비밀번호는 코드 기본값으로 두지 않고 환경 변수로만 제공한다. 비밀값은 진행 기록과 저장소에 남기지 않는다.

### Next Steps

1. 운영용 계정 DB와 비밀 관리 수단이 준비되면 실제 저장소·원격 MCP·Redis를 포함한 opt-in RBAC E2E를 실행한다.
2. 배포 환경에서 세션 쿠키의 `Secure` 속성과 HTTPS 프록시 설정을 확인한다.

### Learnings

- 인증 API가 성공해도 CSS가 `hidden` 속성을 덮어쓰면 사용자는 로그인 실패로 인식한다. 인증 상태·DOM 속성·계산된 스타일·실제 화면을 함께 확인해야 한다.
- 초기 세션 복원 요청과 로그인 요청은 동시에 완료될 수 있으므로, 오래된 비동기 응답이 최신 인증 UI 상태를 덮어쓰지 않도록 방어해야 한다.
