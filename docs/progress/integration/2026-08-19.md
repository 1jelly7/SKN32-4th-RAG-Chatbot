`session_summary.md`(1~3번 항목) 이후 진행분입니다. 무엇을 왜 고쳤는지, 검증은

## 1. 실시간 웹 검색 기능 추가

**왜**: 기존엔 "오늘 환율 얼마야?" 같은 질문에 항상 "실시간이라 답변 못 드립니다"로
끝났음. Tavily 검색 API를 붙여서 실제로 답하게 함.

**핵심 설계**: document/database와 동일한 `{type, content, score}` evidence 계약을
그대로 따름 — `content` 키로 넘기면 기존 `sanitize_evidence()`가 프롬프트 인젝션
필터를 **자동으로** 적용해줘서 별도 방어 코드가 필요 없었음.

| 파일 | 내용 |
|---|---|
| `mcp_servers/web_tools/search.py` (신규) | Tavily 호출, evidence 표준 형태로 변환 |
| `app/core/config.py` | `tavily_api_key` 필드 추가 |
| `app/agent/nodes.py` | `answer_synthesis`에 `web_search` DI 파라미터 추가 (테스트가 fake 주입 가능하도록) |
| `app/agent/graph.py` | `build_graph`에 `web_search` 배선 |
| `app/agent/llm.py` | `_stringify_evidence`에 web 분기 |

Jira 때와 달리 `app/schemas/mcp.py`, `InProcessMCPPort`, 권한 정책은 **안 건드림**
— 웹 검색은 권한 검사가 필요 없는 공개 정보라 MCP envelope 전체를 안 태움.

## 2. 실시간성 트리거 배선 누락 버그 발견·수정

**왜**: 웹 검색을 붙이고 실사용 테스트를 하다가, "오늘 환율 얼마야?"처럼 키워드가
분명히 있는 질문도 웹 검색이 전혀 트리거 안 되는 걸 발견. 로그에 모든 요청이
`labels=[]`로 찍힘.

**원인**: `query_classification.py`의 `classify_question()`(FRESHNESS_SENSITIVE 등
판단)이 **정의만 되어 있고 코드베이스 어디에서도 실제로 호출된 적이 없었음** —
그래프 어디에도 배선이 안 돼 있어서 `state["query_labels"]`가 실제 운영 경로에서는
항상 빈 리스트였음. 이번에 웹 검색을 처음 실사용 경로로 태워보면서 처음 발견됨.

| 파일 | 내용 |
|---|---|
| `app/agent/nodes.py` | `router()`가 `classify_question(question)`을 호출해 `query_labels`에 채우도록 배선 연결 |

**검증**: 회귀 테스트 2개 추가(신선도 질문에서 라벨이 실제로 찍히는지 / 일반
질문에선 안 찍히는지).

## 3. 트리거 키워드 한계 보완 — 방법 B(LLM 자가 판단) 하이브리드

**왜**: 키워드 목록("오늘", "환율", "금리" 등)에 없는 표현("지금 비트코인 시세",
"삼성전자 주가")은 여전히 안 잡힘. 목록을 아무리 늘려도 표현을 다 못 잡는 근본
한계가 있음.

**방식**: 분류 전용 LLM 호출을 매 요청마다 추가하는 대신(비용 큼), **키워드로
못 잡은 경우에만** LLM에게 "답할 수 있으면 답하고, 실시간 정보 필요하면
`NEEDS_LIVE_SEARCH`라는 단어만 출력하라"고 먼저 물어봄. 마커가 있으면 검색,
없으면 그 시험 답변을 그대로 최종 답변으로 사용.

| 파일 | 내용 |
|---|---|
| `app/agent/prompts.py` | `FRESHNESS_ESCAPE_HATCH_PROMPT`, `NEEDS_LIVE_SEARCH_MARKER` 추가, `PROMPT_VERSION` v7→v8 |
| `app/agent/nodes.py` | `answer_synthesis`에 하이브리드 로직(키워드 우선 → 안 잡히면 시험 호출) |

**비용 구조**: 실시간성과 무관한 질문(대다수)은 추가 비용 없음, 진짜 필요한
질문만 시험 호출 1회 추가.

## 4. 실사용 테스트 중 발견한 버그 2건 (2026-08-19)

**"적극행정 개정사항 알려줘"**를 실제로 테스트하다가 연쇄로 발견:

### 4-1. 무관한 사내문서가 임계값을 넘어 오답 근거로 채택됨
`top_score=0.595`(임계값 0.58)로 "적극행정"과 전혀 무관한 사내규정 문서가
근거로 잘못 채택되고, 그 위에 LLM이 존재하지 않는 조항("적극행정 운영규정
제2조")을 지어냄. 원인은 두 가지가 겹친 것으로 판단:
- sbert가 "제1조(목적)" 같은 정형화된 행정 문체 자체를 유사하다고 착각 (기존에
  경고했던 (a)번 방향 — 청킹 개선 필요, 아직 미해결)
- `ANSWER_PROMPT`가 "조항을 기재하라"고만 지시해서 근거에 없는 조항 번호를
  LLM이 지어냄

### 4-2. 웹 검색 출처가 화면에서 안 보임 + 조항 번호 재발
router 버그 수정 후 재테스트하니 이번엔 `route=GENERAL`로 Tavily가 정상
호출됐는데, 그런데도 화면에 출처 카드가 안 뜨고 "적극행정 운영규정 제2조"
같은 조항 번호가 또 나옴. 원인 2가지:

| 파일 | 버그 | 수정 |
|---|---|---|
| `app/web/chat.js` | `renderSources()`가 `source_type === 'document'`만 필터링해서 `web` 출처가 화면에서 통째로 사라짐 | 웹 출처 전용 렌더링 분기 추가 (제목+URL 카드) |
| `app/agent/prompts.py` | `ANSWER_PROMPT`가 문서/DB 근거만 염두에 두고 "조항·페이지 기재"를 지시해서, 웹 근거에도 없는 조항 번호를 LLM이 지어냄 | 웹 근거는 조항 번호 없이 제목·URL만 쓰라는 예외 지시 추가, `PROMPT_VERSION` v8→v9 |

**검증**: 재테스트 결과 출처 카드에 실제 URL(`law.go.kr`, `mois.go.kr` 등)이
정상적으로 떴고, 조항 번호 날조가 사라짐을 확인.

**남은 이슈**: `search_web()`이 Tavily 상위 5개를 관련도 점수 필터링 없이 그대로
근거로 씀 — 실제로 "적극행정" 질문에 `기상청 날씨누리` 링크가 근거로 섞여
들어온 사례 발견. 최소 점수 필터 추가는 다음 단계 후보로 남김.

## 5. Docling 이미지 캡셔닝 통합

**왜**: handoff 문서에 원래 있던 미해결 항목 — "PDF 내 표/이미지 처리 한계
(구조 없이 텍스트만 추출, 이미지는 완전 소실)".

**설계**: PDF에서 이미지를 추출해 기존 OpenAI 모델(`gpt-4o-mini`, 비전 가능)로
캡션을 달고, `[이미지: 캡션]` 형태로 해당 페이지 텍스트 안에 끼워넣음.
`chunking.py`/`index.py`는 전혀 안 건드림 — 캡션이 그냥 일반 텍스트처럼
청킹·임베딩됨.

| 파일 | 내용 |
|---|---|
| `ingestion/loaders.py` | `load_pdf_docling()`, `load_pdf_with_docling_fallback()` 추가 |
| `app/core/config.py` | `enable_docling_captioning` 필드 추가 (기본 `False`) |
| `tests/unit/test_docling_loader.py` (신규) | Docling 변환을 monkeypatch로 대체한 단위 테스트 3개 |
| `scripts/verify_docling.py` (신규) | 특정 PDF 내용에 의존하지 않는 독립 검증 스크립트 |

**안전장치**:
- 기본 꺼짐(`ENABLE_DOCLING_CAPTIONING=false`) — 명시적으로 켜지 않으면 기존
  pypdf 경로 그대로 동작
- Docling 변환 중 예외가 나도(모델 다운로드 실패, API 오류 등) 재인덱싱 전체가
  안 죽고 자동으로 pypdf 폴백

**검증**: 실제 Docling 라이브러리를 설치해 클래스 필드를 직접 검사해 코드의
정확성을 확인(`prov[0].page_no`, `annotations[].kind` 등). 다만 샌드박스 자체
네트워크 제약으로 실제 레이아웃 모델 다운로드까지 포함한 종단 테스트는 로컬
환경에서 사용자가 직접 확인함 (아래 6번 항목 참고).

## 6. "내부정보 우선, 없으면 웹검색" 정책 추가

**왜**: 지금까지는 `DOCUMENT` 라우트가 사내 자료에서 근거를 못 찾으면(`INSUFFICIENT`)
바로 "못 찾았습니다"로 끝났음. 사용자 요구: 사내 자료를 항상 먼저 보되, 없을
때만 웹 검색으로 보충하고 싶음.

| 파일 | 내용 |
|---|---|
| `app/agent/nodes.py` | `DOCUMENT` 라우트의 `INSUFFICIENT` 분기에 웹 검색 폴백 추가. `DATABASE`/`BOTH`는 매출·구매 같은 사내 고유 데이터라 대상에서 제외 |

**주의해서 고친 부작용**: 이 변경을 그대로 넣으면, 기존 테스트 중 `build_graph()`로
전체 그래프를 돌리는 테스트 2개가 `TAVILY_API_KEY`가 설정된 실제 환경에서
**진짜 네트워크 호출을 타는** 부작용이 있었음 — 두 테스트에 가짜 웹 검색 함수를
명시적으로 주입해 항상 결정적으로 동작하도록 같이 수정.

**검증**: 신규 테스트 3개(웹 폴백 성공/실패, `DATABASE`는 폴백 안 하는지) +
기존 테스트 2개 안전장치 추가.
