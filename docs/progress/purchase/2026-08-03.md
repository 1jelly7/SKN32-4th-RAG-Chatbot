### Learnings
- 공유 MySQL 서버에서 여러 팀원이 병렬로 같은 셋업 가이드를 실행하면,
  한쪽이 스키마를 바꾸는 도중 다른 쪽이 옛 스키마로 이미 적재를 끝내는
  경합이 생길 수 있다 — DB 상태를 먼저 실측(`SHOW TABLES`/`SHOW COLUMNS`)
  하지 않고 코드만 보고 판단하면 이런 충돌을 놓친다.
- `SQL SECURITY DEFINER` 뷰 + EXPLAIN 조합에서, admin 계정이 도메인마다
  다르면(sales는 공용 JangGGo, purchase는 전용 계정) EXPLAIN 클라이언트도
  그 도메인의 실제 admin 계정을 써야 한다 — sales 코드를 그대로 복붙하면
  이 부분에서 조용히 깨진다.
- 예전에 수동으로 만든 계정(`purchase_reader`@`localhost`)이 새로 만든
  같은 이름의 `@%` 계정과 별개로 남아있으면, 어느 쪽으로 접속되는지에
  따라 권한 검증 결과가 달라진다 — 계정 재설계 시 기존 계정 잔존 여부를
  항상 먼저 확인해야 한다.
