### Learnings
- MySQL `SQL SECURITY DEFINER` 뷰는 일반 `SELECT`는 뷰 생성자 권한으로 통과하지만
  `EXPLAIN`은 호출 계정이 원본 테이블 권한을 직접 가져야 한다(에러 1345) — EXPLAIN 전용
  admin 클라이언트를 분리하면 최소 권한을 유지하면서 사전 검증을 할 수 있다.
- 프롬프트에 지표 정의를 "이 뷰의 이 컬럼"으로 못 박아도, 그룹화 기준(예: 고객별)이
  바뀌면 LLM이 다른 컬럼(라인 합계)으로 슬쩍 바꿔 쓸 수 있다 — 실제 OpenAI 호출로
  검증해야 이런 회귀를 잡을 수 있었다.
- MCP 공통 envelope가 `rows`/`generated_sql`/`elapsed_ms`만 통과시키는 구조라, 도메인이
  아무리 풍부한 `metadata`를 만들어도 상위 계층 확장 없이는 사용자에게 닿지 않는다 —
  이런 제약은 구현 전에 실제 코드를 읽어야만 알 수 있었다(SPEC.md 초안은 이 제약을
  몰랐던 상태로 작성됨).
